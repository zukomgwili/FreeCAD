# FreeCAD-5ar: ordinary MPC Tie output qualification

This is a source/output-method qualification, not an Oomakhi engineering result or an installation receipt. Production implementation is commit `8e79820eb3b73d01a11c31c1bab84ef5735f81a7`. The final machine-readable gate receipts are linked from `freecad-5ar-validation.json`.

## What changed

The optional native CalculiX ledger now generates `CCX_FORCE_ACCOUNTING_V2` requests. Each requested cut body has separate physical `LOAD`, `CONTACT`, and aggregate `MPC` wrenches. The cut is `-(LOAD + CONTACT + MPC)` on the explicitly selected body. Support residuals and every moment use the declared original global frame and origin; writer units are N and Nmm.

The native implementation uses unprojected internal force, actual physical nodal loads, and the actual homogeneous constraint graph. Topological elimination solves the dependent transpose system, then assembles the net constraint action at its original nodal application positions. Contact internal contributions must not be subtracted a second time. This is neither combined RF nor stress-integrated SOF/SOM, and aggregate MPC action is not an individual Tie multiplier, per-Tie force, or a substitute CF row.

An ordinary Tie no longer needs a dummy Contact. Mixed ordinary Tie and finite-penalty contact are qualified. The supported domain remains one small-displacement static step, C3D4/C3D10 solids, fixed six-DOF native RBE support ports, and explicit unambiguous cut-body ownership. Body SPCs, MPCs touching shared cut nodes, repeated/nonfinite pivots, nonzero dependency cycles, changed reference coordinates, adjusted ordinary Ties and cyclic symmetry refuse explicitly. Ordinary Ties require `ADJUST=NO`. A contact adjustment parameter is not itself a refusal when native coordinates remain unchanged; an actual native coordinate change is.

The existing saved `Fem::ContactSideObservation`, factory and editable `Contacts` property accept ordinary Ties as well as Contacts. Native slave/master order and owner identities are retained even when native LinkSubList storage coalesces adjacent faces belonging to one object. The point is still an authored existing vertex on both bounded faces. Each side uses its own original node, or the existing owner-restricted native VTK surface route. No project-side interpolation or assumed zero Tie displacement was added.

Contact-only observation payloads retain `FreeCAD.CONTACT_SIDE_OBSERVATION_V1`. A Tie or mixed selection uses `FreeCAD.INTERFACE_SIDE_OBSERVATION_V2`, with an explicit constraint kind on every row. Literal old force-ledger V1 data remains readable, without invented MPC values or V2 frame claims. Old requests and old V1 movement sources must be regenerated by the normal writer/solver before new qualification; compatibility does not mean re-attesting historical V1 output as V2.

## Verification meaning

The actual local native failures were reproduced before reading the corresponding implementation: the V1 solver refused a required MPC-touched body; saved observations rejected an ordinary Tie; the GUI command omitted a selected Tie. Setup failures are retained separately and are not capability evidence. Later real contact adjustment and a retained non-decascaded native Tie/RBE dependency graph exposed two additional boundaries; both were fixed and retested.

Independent analytical references, ownership incidence and original native IDs are used instead of treating the parser's own equilibrium identity as an oracle. Force and original-origin moment gates retain the predeclared 1% norm limit with respective 1 N and 1 Nmm denominator floors. The wire consistency check remains a separate `1e-12` requirement.

Qualification covers eight native analytical cases with 144 force/moment checks and two expected domain refusals; 48 legacy V1 contact/cut cases and six refusals; mixed four-body native Gmsh/writer/solver accounting with both paired cuts and simultaneous nonzero contact/MPC action; independent nonzero original-ID displacement; nonconformal native master-side observation without a dummy Contact; GUI selection order; and literal history/edit/save/reopen behavior. Thirteen artificial native-C scheduler units are supplemental algebra/guard tests, not physical solver qualification.

Cold restoration retains literal observation/accounting data but marks the observation Historical and accounting Stale. Recompute does not silently make them current. Explicit observation refresh may revalidate an unchanged bound original field, as in the prior Contact interface; it cannot promote accounting to Current. Only a normal fresh writer/solver run establishes new current accounting. No status, fingerprint, output hash or original ID is repaired to obtain a pass.

The public native regressions are registered in `TestFemApp` as `TestTieAccountingNative`; the GUI selection regression is in `TestFemGui`. These require native Gmsh, the V2 solver and the relevant native VTK wrappers. The local final gate verifies all four new native methods actually execute without skips. Portable analytical helpers and byte-identical historical witness snapshots are retained in `freecad-5ar-qa/`; its index distinguishes executed evidence from runnable copies. Local macOS/POSIX supervisors are not cross-platform application tests.

## Rebuilding and deployment

Build the separate CalculiX extension using `calculix-9zt-probe/build_probe.py`, the official pinned 2.23 source archive, the pinned recipe and the production `forceaccounting.c`/`hooks.patch`. Its build receipt records the binary, source and dependency identities. Configure FreeCAD with `FREECAD_NATIVE_CCX_ACCOUNTING` pointing at that V2 executable; the ordinary user ccx preference is not replaced. Then build through the repository's frozen Pixi environment and run the registered FEM application/GUI suites and CTest serially with isolated profiles. Never overlap native suites with builds or another solver.

The final local CTest gate uses an explicitly reported dot-free private temporary directory because separate open bead `FreeCAD-8rk` affects extensionless files below dotted ancestors. No CTest case is omitted and that unrelated bug is not claimed fixed. No application bundle was replaced for this task.

## Oomakhi remains unaccepted

No original Oomakhi model was opened, altered or solved. Frozen notes were inspected read-only. The adopted amended-r02 sampling definition is still 97 pairs/194 vectors: 72 Slave/1, 24 Master/1 and one Slave/5. The retained selector interface can express these same three batches; its 24 rear-side two-face selections fit ordinary non-cyclic, unadjusted Ties. This is interface applicability, not a new result or permission to substitute different samples.

Any later engineering run must independently bind the exact original-to-Tie object/reference map, original XYZ/frames, fresh V2 provenance, all 194 owner-side vectors, 48 raw original-ID pairs, eight separate support controls, and overclosure/slip obligations, together with complete support and both cut force/original-origin moment checks. The frozen 193-contact engagement/transfer/area/state duties and the 96 initially gapped engagement-only pockets are also retained. A later independently reviewed Tie method must account for these duties explicitly; aggregate MPC action must not be relabelled as per-Tie CF or silently substitute for that output scope.

Geometry, loads, reference signs, norms and the force/moment denominator-floor rules are unchanged. The separate fixed 194-vector 5% comparison requires a finite positive reference norm and has no invented denominator floor. No engineering acceptance rule is loosened by the new source capability.

R49 remains failed at **11.123267892% against 5%**. Earlier equilibrium failures remain historical failures. This source capability does not accept physical anchorage, stress accuracy, mesh convergence, the whole house, R30, BIM adoption or an upstream contribution, and does not authorize an automatic building-side solve.
